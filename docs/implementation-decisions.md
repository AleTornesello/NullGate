Date: 2026-11-09. Scope: Tasks 1–5 contracts and implementation from [the implementation plan](superpowers/plans/2026-11-09-nullgate-implementation.md).

These are implementation contracts, not claims of working proxy services. Task 2 implements the shared rule engine only. The four specification documents remain the requirements authority; this document resolves their implementation details. No application behavior is added in Task 1.

## Matching and import contracts (Task 2)

All normalization is shared by rule ingestion, DNS queries, HTTP authorities and CONNECT targets. Normalize before comparing; never use a URL parser that silently rewrites a different path than the contract below.

| ID | Selected behavior | Rationale | Required tests in `nullgate-core/tests/rules.rs` |
| --- | --- | --- | --- |
| M1 | Hostnames use IDNA UTS #46 non-transitional processing with STD3/label and DNS-length validation, then lowercase ASCII A-labels. Remove one final ASCII dot; reject additional trailing dots, empty labels, underscores, invalid A-labels and overlong names. Apply the same process after removing a domain rule's optional leading `*.`. | Unicode/A-label and case equivalence without accepting ambiguous hostnames. | `EXAMPLE.com.` equals `example.com`; `bücher.example` equals `xn--bcher-kva.example`; invalid labels and double final dots rejected. |
| M2 | Domain patterns are an exact normalized hostname or `*.` plus that hostname. Wildcards match one or more whole labels, including nested labels, never the apex. IP literals are not domain rules; DNS names are never resolved during parsing. | Preserve agreed domain semantics and avoid suffix confusion. | Existing specification examples; `badexample.com` never matches `*.example.com`; URL-only host never blocks DNS. |
| M3 | Accept case-insensitive HTTP/HTTPS schemes only. URL authority has one exact hostname or canonical IP literal; no wildcard, userinfo, percent-encoded host, zone ID, or backslash. Strict dotted-decimal IPv4 and bracketed IPv6 are supported in URLs/CONNECT; reject alternative numeric IPv4 spellings. IPv6 comparisons use address bytes. | Avoid authority reinterpretation and authentication leakage. | Mixed scheme case, IDNA host, IPv4/IPv6, credentials, ambiguous numeric hosts, malformed authorities. |
| M4 | Match `(scheme, normalized host, effective port, canonical path)`. Omitted HTTP port is 80; HTTPS is 443. Explicit defaults equal omitted defaults. Other ports match only the same port; valid ports are 1–65535. Domain rules apply at every port. CONNECT must include an explicit valid port. | Nondefault-port rules must not broaden to all services. | Default-port equivalence; 8443 differs from 443; invalid/empty ports; CONNECT parsing. |
| M5 | Empty URL path becomes `/`. Paths are case-sensitive. Preserve repeated slashes and trailing slashes. Encode literal non-ASCII path characters as UTF-8 percent bytes. Reject raw spaces, controls and backslashes. | Stable byte-level matching without collapsing distinct resource paths. | `/Ads` differs from `/ads`; `/ads` differs from `/ads/`; `//ads` differs from `/ads`; Unicode path equivalence. |
| M6 | Validate every percent triplet, uppercase its hex digits, and decode only ASCII unreserved bytes (`A-Z a-z 0-9 - . _ ~`). Then remove complete `.`/`..` path segments using RFC 3986 section 5.2.4, including decoded `%2E` segments, retaining repeated separators. Do not decode reserved bytes or recursively decode escapes. Reject percent-encoded ASCII controls. | Consistent equivalent paths while preserving encoded separators as data. | `/a/../ads` and `/%61ds` match `/ads`; `%2f` becomes `%2F` and differs from `/`; `%252F` stays double-encoded; invalid escapes rejected. |
| M7 | Strip the query at the first literal `?` before path normalization, for rules and requests; `?` is never a wildcard. Reject literal fragments in rules and proxy request targets. `%3F`/`%23` remain path bytes. | Queries are explicitly ignored; fragments cannot be enforced on the wire. | `/ads?x=1` equals `/ads`; fragment rule diagnostic; encoded delimiter remains distinct. |
| M8 | Each raw `*` in the rule path is a wildcard matching zero or more canonical path bytes, including `/`. `%2A` is a literal encoded asterisk and does not become a wildcard. No regex, escape syntax or character-class syntax is supported. Raw `[`/`]` in rule paths are rejected; encode literal brackets. Regex/adblock/hosts-file lines and domain/path wildcard combinations are malformed, not guessed. | One small grammar, no silent conversion from incompatible formats. | `*`, nested path matching, `%2A`, unsupported list formats; `?` remains a query delimiter. |
| M9 | A final literal `/*` also matches the canonical parent path after removing that suffix; all other wildcards keep ordinary zero-or-more semantics. `/ads/*` matches `/ads`, `/ads/`, descendants, never `/adsense`. Root `/*` covers `/` and every path. | Preserve the specified special case without prefix broadening. | All original wildcard examples; exact `/ads` versus `/ads/`; parent boundary; root. |
| M10 | Input is UTF-8 (invalid UTF-8 rejects the upload, with no write). Accept LF/CRLF and a single UTF-8 BOM at the start. Trim ASCII space/tab at both line ends; skip empty lines and lines whose first remaining character is `#`. No inline comments: `example.com # note` is malformed, a URL `#` fragment is malformed. Other whitespace is not trimmed. Diagnostics use original 1-based line numbers. | Predictable imports, no silent truncation. | BOM, CRLF, indentation, inline comment, non-ASCII whitespace, mixed valid/invalid input. |
| M11 | Deduplicate by typed canonical rule within each provenance group; report duplicates separately from malformed lines. Retain source membership even when effective rules overlap. The compiled global union deduplicates without losing provenance in storage. No allow rules or ordering precedence. | Deleting one source must not delete an independently supplied rule. | Case/query/default-port duplicates; overlapping sources; domain block wins over URL permit. |
| M12 | Initial bounds: 4 MiB decoded UTF-8 import body, 8 KiB per raw rule line, 100,000 unique effective rules per candidate policy. An overlong line is malformed; whole-body or policy-capacity excess fails the mutation without publication. Compile wildcard tokens and use iterative bounded matching (O(pattern bytes × path bytes), no recursive backtracking); cap request target at 8 KiB with HTTP 414. | Bound resource use and adversarial wildcard work. | Limit boundaries, many-star patterns, long paths, capacity rejection preserves old snapshot. |

Do not apply WHATWG dot-segment/percent or host heuristics before these checks. Runtime matching uses the path actually forwarded under this canonicalization contract; forwarding preserves the original valid target/query, so upstreams may still interpret reserved escapes differently. NullGate does not claim application-specific path equivalence. Tests must cover canonicalization independently from any protocol library.

### Shared API shape

These Rust contracts were planned in Task 1 and are implemented in Task 2. Private fields and fallible constructors prevent unnormalized values reaching matching code.

```rust
parse_blocklist(input: &str) -> ImportReport
normalize_host(input: &str) -> Result<NormalizedHost, HostError>
normalize_url(input: &str) -> Result<NormalizedUrl, UrlError>
RuleSet::compile(rules: impl IntoIterator<Item = Rule>) -> Result<RuleSet, CompileError>
RuleSet::blocks_domain(&self, host: &NormalizedHost) -> bool
RuleSet::blocks_url(&self, url: &NormalizedUrl) -> bool
RuleSet::requires_inspection(&self, host: &NormalizedHost) -> bool
```

`Rule` is `ExactDomain(DomainName)`, `Subdomains(DomainName)`, or `Url(UrlPattern)`. `DomainName` is opaque and validated; `NormalizedHost` distinguishes DNS, IPv4 and IPv6. `NormalizedUrl` holds `HttpScheme`, host, effective `u16` port and canonical path. `UrlPattern` retains the canonical rule URL; `RuleSet::compile` produces wildcard tokens and the optional trailing-`/*` parent alternative. Normalizing a request never creates wildcard tokens.

`ImportReport` carries accepted unique rules with original line numbers, malformed diagnostics (`line`, stable `code`, safe message), duplicate line references and ignored-line count. It does not persist or publish. Empty input is a valid empty report; mutation semantics distinguish explicit list clearing from protected remote refresh. The ingress layer enforces the byte limit before calling the parser. No DNS or network I/O occurs in these functions.

## Configuration, persistence and publication

| ID | Selected behavior | Rationale | Affected tests |
| --- | --- | --- | --- |
| S1 | Versioned TOML startup configuration: `schema_version`, DNS UDP/TCP listener addresses, HTTP and web listeners, data directory, ordered DNS upstream socket addresses, timeouts/limits, and tagged `local`/`oidc`/`none` web-auth mode (default local). Unknown keys, unsupported versions and invalid cross-field combinations fail startup with key-specific errors. Relative data paths resolve against the configuration file directory. | Catch typos and avoid dependence on working directory. | Task 3 storage/config: malformed/unknown fields, version and path handling, no secrets in errors. |
| S2 | TOML owns startup/listener settings; SQLite owns blocklists, provenance, accounts, sessions and policy revision. No duplicated mutable setting in both stores. Startup-setting edits require restart and must be labelled as such. Rule edits are live. Secret config uses protected file references, not downloadable settings. | Single source of truth; do not promise live rebinding. | Tasks 3, 8–10: restart persistence; UI/API accurately distinguish saved from active startup settings. |
| S3 | SQLite with bundled SQLite, foreign keys, schema migrations, WAL and `synchronous=FULL`; one serialized writer on a bounded blocking worker, never SQLite work on an async reactor thread. Candidate compilation occurs before the write transaction. Persist each logical mutation and its new revision in one transaction. | Durable changes and straightforward concurrency without an external database service. | Tasks 3–4: rollback, restart recovery, migration failure, busy/disk errors, atomic multi-entry mutations. |
| S4 | Store named lists and independent manual, file-import and remote-source membership groups. | S5 | Remote refresh atomically replaces that source only when at least one valid rule exists (duplicates count as valid). Fetch failure does not change effective rules. | User-confirmed preservation policy. | Task 11: disappearing remote rules, partial validity, empty/all-invalid/duplicate-only responses, other-source/manual preservation. |
| S6 | Require `expected_revision` on every mutation, including refresh. Serialize writes and reject stale revisions with conflict; never last-writer-wins. | S7 | Build the complete immutable `PolicySnapshot { revision, rules }`, validate limits, commit SQLite, then atomically replace the core-owned Tokio watch state (active `Arc<PolicySnapshot>` or unavailable revision; Task 4 refinement). Core owns read/subscription contracts and a `PolicyManagement` write trait; orchestrator implements the writer; web receives an injected `Arc<dyn PolicyManagement + Send + Sync>`. Readers borrow one snapshot per request. No web-to-orchestrator dependency. | Durable state precedes visibility; one version includes domain, URL and inspection sets. | Task 4: complete snapshots, existing subscriptions, failed writes, no crate cycle. |
| S8 | Success is returned only after publication and required connection invalidation acknowledgements. A pre-commit validation/storage error means no revision was applied. A post-commit activation failure is explicitly `committed_not_active` with committed revision; stop accepting affected traffic, mark unhealthy and rebuild from committed storage before readiness. Never report it as an ordinary unsaved failure. Crash after commit recovers that revision at startup. | SQLite commit and in-memory activation cannot be one atomic operation. | Tasks 4, 8, 13: injected failure before/after commit, restart recovery, no misleading success/retry. |
| S9 | DNS/HTTP requests admitted after save acknowledgement use the published revision. Existing tunnels close on new domain blocks or changes in inspection membership (add or remove). Inspected keep-alive requests reevaluate each request. In-flight work admitted under the old snapshot may finish; already sent responses cannot be undone. | Concrete live-update boundary. | Tasks 4–7, 13: old handle observes update; tunnel invalidation; add/remove target; in-flight boundary. |
| S10 | Management operations return revision, accepted/duplicate/malformed counts and line diagnostics. JSON API uses 400 malformed envelope, 401 unauthenticated, 403 forbidden, 409 revision conflict, 413 body limit, 422 invalid operation/capacity/no-valid-refresh, 502 fetch failure, 503 pre-commit storage failure or committed-not-active (distinct machine code and revision). Valid-subset imports return success with diagnostics. HTML uses the same service results. | UI and crafted API requests receive the same authoritative outcome. | Tasks 4, 9–11: status/code/side-effect matrix; output escaping; no secret/raw credential echo. |

The repository interface in core provides list/read-by-revision, transactional candidate mutation and source memberships. Its SQLite implementation may remain in core; core has no **internal workspace** dependencies, not a prohibition on third-party libraries. Policy reader interfaces never expose storage handles. Administrative routes live under `/api/v1`; list responses carry revision and mutations supply `expected_revision`. Read-only requests do not require a write lock.

## Task 2 matching clarifications and implementation record

Task 2 implements only parsing, normalization, compilation and matching. Before implementation, the following gaps in the planned APIs were resolved:

| Decision | Resolution and rationale | Tests |
| --- | --- | --- |
| Safe domain construction | Domain variants carry an opaque `DomainName`, not arbitrary `NormalizedHost`, so callers cannot construct IP domain rules. `NormalizedHost` distinguishes DNS/IPv4/IPv6. `Rule::parse` is the fallible single-rule constructor. Single-label DNS names are accepted. IDNA maps Unicode dot separators before removing one root dot; numeric-final-label names and alternative numeric IP spellings are rejected to prevent downstream URL reinterpretation. Only raw canonical dotted IPv4 is accepted as IPv4; IPv6 host input is bracketed. | Host validation, IDNA, numeric hosts and IP-domain rejection. |
| Domain versus URL checks | `blocks_domain` consults domain rules only. `blocks_url` combines domain blocking with matching URL rules. `requires_inspection` selects exact HTTPS-rule hosts but returns false for an already domain-blocked host, which must be rejected before decryption. | DNS isolation, domain precedence, inspection selection. |
| Query and path grammar | Strip queries without decoding or validating their percent escapes; raw whitespace/controls/backslashes and literal fragments are rejected anywhere in the URL, including query text. Accept RFC 3986 path characters plus raw Unicode (UTF-8 encoded); reject other raw ASCII delimiters, including brackets. Consecutive stars remain distinct canonical rules but compile to one wildcard token; wildcard matching uses bytes, as M12 specifies. Dot segments normalize before wildcard compilation, including when removing a segment containing `*`. | Query boundary, invalid URLs, canonical path and wildcard tables. |
| Port syntax | Ports contain ASCII decimal digits only; leading zeroes normalize to the same effective port. Generic authority parsing is available with an optional default port; absence of a default requires an explicit port (CONNECT). | Port and CONNECT-authority tests. |
| Import resource errors | Parser additionally rejects bodies above 4 MiB with report-level `fatal_error` and no partial accepted output; `&str` guarantees valid UTF-8. Line limits count raw UTF-8 bytes excluding LF/CRLF and the initial BOM, before trimming or comment handling. Lone CR is malformed. Deduplication is per parse call; storage/provenance stays in Task 3. | Input limits, line numbering, empty and mixed reports. |
| Compilation bounds | Enforce 100,000 distinct canonical rules, counting only unique rules. Keep exact/suffix domain indexes and URL patterns grouped by scheme/host/effective port; inspection hosts have a separate index. Immutable matching uses no I/O. Iterative last-star wildcard matching has O(pattern × path) worst-case work and constant scratch space. | Compile limit, duplicate union, adversarial wildcard and exhaustive small-case comparison. |

These are technical rulings within Task 1's matching contract; no additional product choice blocks Task 2. Their tradeoff is strict rejection of ambiguous host/URL input rather than browser-specific reinterpretation. The shared API is finalized in `nullgate-core` rustdoc. Later tasks must enforce protocol-specific status codes (such as HTTP 414); the engine returns typed normalization errors only.

## Task 4 policy publication contracts

Task 4 adds orchestration of the existing blocking repository, not proxy services or web endpoints. Work stays on the user-selected `develop` checkout.

| Decision | Selected behavior and rationale | Tests |
| --- | --- | --- |
| Immutable read boundary | `PolicySnapshot` privately owns one repository snapshot and its compiled `RuleSet`; readers hold `Arc` values and compare one revision for all decisions. A core-owned watch channel carries either an active snapshot or an unavailable state with the last known/committed revision. This refines S7's planned `watch<Arc<PolicySnapshot>>` payload so availability and policy cannot disagree. Services receive only subscription capabilities; the writer stays in orchestration. Watch notifications can coalesce intermediate revisions; `current` always sees the latest complete state. | Existing DNS/HTTP/TLS subscribers, immutable old handles, concurrent complete-state observations, late subscribers. |
| One bounded writer | A dedicated Tokio blocking task owns the repository. A bounded MPSC queue serializes validation/commit/activation/publication; queue saturation rejects before acceptance. No SQLite work runs on the async reactor. Import and metadata byte limits are checked before enqueueing. Expected revisions are mandatory and never automatically retried. | Concurrent same-revision edits, saturation, responsive readers while storage is blocked, failed validation/write. |
| Save acknowledgement | Without activation participants, commit then atomically publish before replying. With participants, mark the committed revision unavailable while their idempotent invalidations run, publish only after all acknowledge, then reply. New admissions must obtain `current`; already admitted requests may retain an older immutable snapshot. Participants have a shared bounded deadline (default 5s). Actual tunnel tracking belongs to Tasks 7/13. | Publication before return, gated activation, activation failure/deadline, no partial state. |
| Failure and recovery | Pre-commit repository errors leave the active policy untouched. Explicit recovery reloads and compiles durable state, repeats idempotent activation from the last healthy snapshot, and republishes before reporting recovery. | Cancellation and shutdown | Once a command is enqueued, caller cancellation does not cancel commit/publication. | Injected management API | Core exposes an object-safe `PolicyManagement: Send + Sync` trait using boxed Send futures, and save results include the full parser import report. ## Task 5 DNS transport contracts

Task 5 implements the DNS library service only; the binary and supervisor integration stay in Task 8.

| Decision | Selected behavior and rationale | Tests |
| --- | --- | --- |
| Lifecycle | Shared core service status/readiness/failure types carry transport/address information without a back dependency. Start binds UDP and TCP before reporting ready; a second-bind failure releases the first socket. Explicit cancellation/owner drop stops listeners and cancels/joins all client/upstream work. Per-query errors do not fail the listener; fatal listener/task errors report Failed. | Ready ports, bind failure/release, monitor status, idle/partial TCP and pending upstream shutdown. |
| DNS grammar | Accept one standard QUERY question, including non-A/AAAA record types and non-hostname DNS labels. Drop packets shorter than a header and received responses; malformed complete queries get FORMERR. Unsupported opcodes, zone transfers and signed-message authentication get NOTIMP. Validate the full frame, including trailing bytes and compression errors. Unsupported EDNS version gets BADVERS. | Malformed/short/compressed packets, query/response distinction, unsupported operation, EDNS. |
| Domain matching | DNS wire names use label boundaries and ASCII case folding, matching IDNA A-label rules. Opaque/non-hostname labels can still be subdomains of a valid wildcard base; add a narrow core wildcard-base membership query rather than interpreting DNS binary labels as URL hostnames. Root/other permitted DNS names are forwarded. Only domain rules are consulted; URL-only hosts resolve. | Exact/apex/nested wildcard, underscore/binary-label descendants, IDNA, root/non-address queries, URL-only host. |
| Synthetic replies | Preserve ID, opcode, question, RD and CD. Set QR/RA; clear AA/AD/TC; NXDOMAIN has no answers or invented SOA. Echo EDNS version 0 with DO and bounded payload, but not arbitrary options. Policy unavailable or exhausted upstreams produce SERVFAIL. | Flags/counts, EDNS and unavailable policy. |
| Association and forwarding | Each request gets an isolated connected upstream UDP socket or TCP connection and a fresh random transaction ID; restore the client's ID on return. Accept only matching QR/opcode/question name/type/class/ID from the configured peer. Ignore malformed/unrelated responses within the existing deadline. Preserve valid upstream wire bytes except ID, including DNSSEC/unknown records. TCP clients use TCP upstream; truncated upstream UDP retries TCP at that same endpoint. | Concurrent colliding client IDs, wrong ID/name/type/class/opcode/source, A/AAAA, truncation fallback. |
| Deadlines/failover | Try configured upstreams in order on timeout/transport failure, using one attempt deadline (including TCP fallback) and the total configured deadline. Valid DNS error replies are forwarded rather than retried. No cache or additional upstream transports. | Unresponsive/invalid upstream, ordered failover, bounded exhaustion, no public DNS. |
| Bounds and TCP framing | Max wire frame is 65535 bytes; UDP responses respect the client's 512-byte or EDNS limit, capped at 1232. Oversized UDP answers get a valid TC reply, never byte slicing. Default 1024 in-flight requests/1024 TCP connections, configurable library limits; UDP overload drops packets and excess TCP connections close. TCP requests are processed sequentially per connection, each with a fresh policy read. Frame/read/write idle deadline defaults to 30s; cancellation interrupts it. | Oversized answer, two-byte framing, reused TCP with live updates, cancellation and limit validation. |

The service captures one policy snapshot at query admission. In-flight queries may finish under that revision; each later query, including on an existing TCP connection, reevaluates current policy. DNS wire names are not passed through URL heuristics. Upstream fixture endpoints are local and tests use ephemeral ports. Actual DNS caching/bypass/client configuration and binary supervision remain later tasks.


Task 5 rejects invalid question counts from the fixed header before full Hickory decoding, preventing attacker-controlled question-vector preallocation and oversized FORMERR replies. Hickory aliases numeric extended response code 16 as BADSIG when decoding; the EDNS BADVERS regression therefore checks wire value 16 and the OPT version rather than enum identity. Dependencies were activated with the existing selected versions and the lockfile updated intentionally; existing locked package versions remain unchanged.
